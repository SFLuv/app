## Features

### The composer follows the keyboard — 0.13h · mobile-app

Reported: the message bar slid up and down noticeably slower than the keyboard.

The cause is the New Architecture. `LayoutAnimation` has no keyboard curve there and falls back to linear
(`calculateAnimationProgress` in React Native's `renderer/animations/utils.cpp`), and every frame
re-rendered the whole screen.

- **2.4.0, over the air.** The lift is an `Animated.timing` that runs for the keyboard event's own
  duration. It uses a Bézier close to the iOS keyboard's curve, `(0.38, 0.7, 0.125, 1)`, and the chat
  body is an `Animated.View`. This is close to the keyboard, not coupled to it: it starts a frame or two
  late, and cannot follow an interactive swipe-down.
- **2.5.0, native.** `react-native-keyboard-controller` 1.18.5, with Reanimated 4.1 and Worklets 0.5.1.
  Native code reports the keyboard's position on every frame, on both platforms and during interactive
  dismissal, and the composer sits on the keyboard's top edge each frame. The provider starts disabled,
  and the chat switches it on only while it is open. On Android, switching it on stops the window
  resizing for the keyboard, which every other text field in the app relies on.

### Reply from a chat push — 0.11h · app + mobile-app

Asked for: swipe down on a message to see the history and reply, Telegram- and iMessage-style, with voice
replies.

- **The category.** Chat pushes now carry the `chat_message` category, with a Reply action that takes
  text. Dictation on the keyboard is the voice reply.
- **The thread URL.** Each chat push also carries a signed thread URL,
  `/push-thread/{id}?r=&exp=&sig=`. It is an HMAC from the push-image signer, valid for 72h.
  - GET returns the history; POST sends a reply as the recipient.
  - The server checks the signature, and that the recipient is active, has accepted the privacy policy,
    and is allowed the chat beta.
  - Query strings are redacted from the logs.
  - It is a bearer capability: whoever holds the URL can post as the recipient in that one chat until it
    expires.
- **In the app, over the air.**
  - The app registers the category.
  - A reply goes through the thread URL, falling back to the signed-in client.
  - A sent reply clears that chat from the tray and updates the inbox.
  - A reply that fails raises a local notification quoting what was typed.
- **Delivery is best-effort in the background.** expo-notifications calls iOS's completion handler at
  once, so a reply sent while the app is not running has little time to finish. The failure notification
  is the safety net.

### Chat list, reads and per-chat counts — 0.10h · app + mobile-app

Three reports:

- A sent message did not show in the chat list until a refresh.
- Opening a chat acked late, or acked only one or two of its messages.
- A chat's count always read "1".

What was wrong, and what changed:

- **Sending.** The server never sends the sender a `message.new` event for their own message, so the
  inbox kept the old preview. The chat cache now keeps each thread's newest message as an overlay, and
  follows edits and deletions to it. The inbox draws through the overlay, re-sorted, and reconciles it
  with every answer from the server.
- **Acks.** The app's own copy of the notification tray raced the re-read on returning to the
  foreground. Opening a chat now clears that chat's notifications by reading the OS tray directly. Pushes
  for the chat that is open are no longer shown at all.
- **Counts.** The Messages tab counted conversations, not messages. The server now returns an
  `unread_count` per conversation, and the tab adds them up.

### Home-screen icon badge — 0.10h · app + mobile-app

Reported: the app icon never showed a count.

- **No push had ever carried a `badge`.** Every push now does (`pushBadge`, in
  `backend/handlers/push_badge.go`). The number is:
  - unread chat messages, where the chat beta is allowed, plus
  - the bell: outstanding notifications and the improver feed's unseen entries, which include W-9 items
    and workflow payouts.
- **After a reply sent from a push**, the server sends a silent, badge-only push, so the icon catches up
  without the app opening. The app shows nothing for it and keeps it out of its own copy of the tray.
- **In the app**, the icon shows unread messages plus the bell. It is set once both counts are known, and
  cleared on sign-out.
- **The improver feed** was added after the W-9 merge showed that the bell counts it (`0b89385`). Without
  it, a push showed one fewer than the bell whenever a W-9 was outstanding.

  stored changes. It is applied in `GetSupervisorWorkflows` (`backend/db/app_workflow.go`), which both the
